# 整理公开仓库

此脚本将当前工作区整理成可用于新公开仓库的文件快照，默认目录为 **`D:\流萤工具箱公开仓库`**。它读取当前磁盘内容，包含尚未提交的修改和符合规则的新文件；不读取历史版本，也不复制源仓库的 `.git`。

需要 Node.js 22 和 Git，在私有项目根目录运行：

```powershell
# 先预览；不会创建或写入目标目录。
npm run prepare:public -- --dry-run

# 导出当前内容。
npm run prepare:public

# 指定其他目录。
npm run prepare:public -- --output 'D:\其他目录\FireflyToolBox'

# 查看完整文件清单、摘要和排除原因。
node scripts/prepare-public-repo.mjs --dry-run --json
```

也可用 `--source '源仓库根目录'` 指定完整 Git 工作区。非 Windows 平台需显式提供 `--output`。`--json` 的结果可重定向到私有工作区中的报告文件，勿把本机路径报告作为公开源码提交。

## 整理规则

- 同时收集已跟踪和符合规则的未跟踪文件，再用当前 `.gitignore` 等 Git 忽略规则检查；已经跟踪、但现在被忽略的文件也不会继续导出。
- 保留源码、README、SKILL、更新日志、示例、验证脚本、锁文件、原生工程和许可说明。`package.json` 中的 `private: true` 用于避免误发 npm 包，不妨碍公开 Git 仓库。
- 保留 Rust 直接引用的内置工具 JS、OCR 模型、字体、Gradle 包装器及自定义 Android 原生代码。`media-assets` 等可重新构建的大型产物不导出；文件整理后按开发指南先安装依赖、生成内置资源再编译。
- 不导出源仓库的 Git 历史、依赖目录、运行数据、缓存、构建产物、旧工具包、本地笔记，以及不符合忽略规则的根目录原型文件。
- 即使被 Git 跟踪，常见环境配置、签名密钥、本地 SDK 配置和凭据文件仍会被排除。对保留的文本检查常见私钥、访问令牌等特征，发现疑似凭据时停止，不打印匹配到的内容。
- 拒绝源文件链接、选中文件路径中的目录联接，以及指向不安全位置的目标路径。目标不能与源目录重叠，也不能是磁盘根目录、用户主目录或 `.git` 目录。

原有第三方许可、模型 NOTICE 和 README 中的授权说明会保留。项目当前对 OCR 模型再分发授权的待确认说明也继续保留；文件整理与凭据检查不等于完成公开发布审核，发布前仍应人工核对内容和授权。

## 重复运行与文件保护

目标目录适合使用空目录，也可事先创建新的公开仓库 Git 目录。脚本不初始化 Git，不设置远端，不提交或推送；目标已有的 `.git` 不会修改。

正常导出会写入本地记录 `.firefly-public-export.json`，只记录相对文件名、SHA-256 和时间，不包含源仓库路径、远端或私有提交 ID。导出的 `.gitignore` 会忽略此记录及本地敏感配置。

下次运行时：

- 未变化的文件保留；源文件更新时，仅替换仍与上次导出摘要一致的目标文件。
- 源文件已删除或不再属于导出清单时，仅移除目标中未经修改的旧导出文件。
- 目标文件被人工编辑，或存在未管理且不属于忽略规则的普通文件时，在写入前停止并列出冲突路径；不会强制覆盖、合并或整目录清空。
- 目标中的 Git 元数据、本地构建缓存及被源工作区忽略规则排除的未管理生成文件继续保留，不进入导出清单；上次记录为导出文件的旧文件仍会检查，不能用新忽略规则绕过人工修改保护。执行期间不要同时编辑源文件或目标目录。

请保留导出记录。记录缺失时，相同文件可以被重新识别，但不同内容和无法确认归属的旧文件需要自行核对，或另选空目录；记录损坏时脚本会停止。

文件先在目标内的临时目录写入并核对摘要，再逐个替换，最后更新记录。文件系统报错或进程中断时不承诺整批回滚；可先重新预览，已写入且与源内容一致的文件可继续识别。如果发现未清理的 `.firefly-public-export-stage-*` 目录，先检查运行进程和文件内容，再自行处理，脚本不会自动清理未知的残留目录。

## 验证与后续发布

```powershell
npm run test:public-export
```

测试覆盖预览、未提交修改、忽略规则、常见凭据、路径重叠、目录联接、人工修改保护、旧文件清理、Git 元数据保留及重复运行。公开目录的构建与验证方法见 [开发与验证](../development/README.md)，工具开发规范见 [SKILL](../../skills/firefly-module-author/SKILL.md)。

检查导出清单与文件后，再在目标目录自行初始化或使用新的公开 Git 仓库，添加文件并核对将要提交的内容。首次提交只使用这个整理目录，原私有仓库的历史不会随文件快照带入。
